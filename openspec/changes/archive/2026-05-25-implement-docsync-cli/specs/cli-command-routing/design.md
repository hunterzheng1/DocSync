## 4. 局部后端接口设计

### 4.1 接口清单

| 接口名称 | 路径 | 方法 | 说明 |
|---------|------|------|------|
| CLI main | `docsync <command> [args]` | 命令行调用 | 主命令入口 |
| Help | `docsync help` | 命令行调用 | 输出帮助 |
| Version | `docsync version` | 命令行调用 | 输出版本 |

### 4.2 接口详细设计

#### 接口 1：CLI main

**基本信息**：
- 路径：`docsync`
- 方法：命令行调用
- 认证：不需要

**请求参数**：
| 参数名 | 类型 | 必填 | 说明 | 约束 |
|-------|------|------|------|------|
| command | string | 否 | 一级命令 | 缺省为 `help` |
| rest | string[] | 否 | 剩余参数 | 保持原始顺序 |
| options | object | 否 | 通用参数对象 | 由 `parseArgs()` 生成 |

**响应结构**：
```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "exitCode": 0
  }
}
```

**业务逻辑**：
1. `bin/docsync.mjs` 调用 `main(process.argv.slice(2))`。
2. `main()` 取第一个 token 为 command，空值归一为 `help`。
3. `parseArgs(rest)` 生成 options，同时保留命令子参数。
4. switch 分发到对应 command handler。
5. 未知命令输出错误和 help，并设置 `process.exitCode = 1` 或抛出带 exitCode 的错误。

## 6. 模块内部逻辑

### 6.1 核心流程

```
[读取 argv]
  --> [识别 command]
  --> [解析通用 options]
  --> [分发 handler]
  --> [handler 输出结果]
```

### 6.2 状态机（如有）

无持久状态机。

### 6.3 关键算法（如有）

- `parseArgs()` 逐 token 扫描；布尔 flag 设置 true；`--cwd`、`--docs`、`--extra` 读取下一个 token。
- `--quiet` 与 `--verbose` 同时出现时，以最后出现的 token 为准，并在 options 中保留最终布尔值。
- 参数缺值时抛出 `CliError(message, 2)`。
