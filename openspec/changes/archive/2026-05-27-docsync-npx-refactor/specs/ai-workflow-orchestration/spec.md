## 1. 需求规格（官方格式）

### 修改需求

#### 需求项：ai/auto 能力折叠

系统必须将旧的 `docsync ai` 和 `docsync auto` 能力折叠到 `/docsync:sync` 指令中。

##### 场景：/docsync:sync 替代 docsync ai

- **当**用户运行 `/docsync:sync`
- **预期**执行旧的 `docsync ai` 的完整同步能力

##### 场景：docsync auto 暂不作为主路径

- **当**用户查询 `docsync auto`
- **预期**提示"此命令暂不作为主路径，可作为后续 CI 模式"

### 新增需求

#### 需求项：同步算法共享

系统必须让 `/docsync:init` 和 `/docsync:sync` 共享同一套同步算法。

##### 场景：init 使用同步算法

- **当**`/docsync:init` 执行到文档创建/更新步骤
- **预期**调用与 `/docsync:sync` 相同的同步算法

##### 场景：sync 使用同步算法

- **当**`/docsync:sync` 执行文档同步
- **预期**调用完整的同步算法（事实提取 → 模式选择 → 编辑应用 → 格式修复 → 报告输出）

## 2. 技术契约（SDD 扩展）

### 2.1 接口定义

#### 同步算法输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| rules.default | file | 是 | 默认规则 |
| rules.override | file | 否 | 覆盖规则 |
| context.repomix | file | 是 | Repomix 上下文 |
| context.git-status | file | 是 | git 状态 |
| target-docs | list | 是 | 目标文档列表 |
| mode | enum | 是 | full / fast |

#### 同步算法输出

| 参数 | 类型 | 说明 |
|------|------|------|
| updated-files | list | 已更新文件列表 |
| skipped-files | list | 跳过的文件及原因 |
| facts-used | list | 使用的项目事实 |
| mode | enum | 使用的模式 |
| todo-review | list | 待审查内容 |
| verification | string | 格式检查结果 |
