# spec.md - 能力规格定义

> **定位**：将 prep 能力内嵌到 init/sync 流程中的上下文准备
>
> **【质量红线】严禁描述模糊；约束必须量化；缺失必要参数时 opsx-check 必须报错拦截
>
>> **【格式要求】** 需求项使用 `####`（4个#），场景必须使用 `#####`（5个#）

---

## 1. 需求规格（官方格式）

### 修改需求

#### 需求项：上下文准备内嵌

系统必须将旧的 `docsync prep` 能力内嵌到 `/docsync:init` 和 `/docsync:sync` 流程中，不再作为独立命令。

##### 场景：init 中的上下文准备

- **当**用户运行 `/docsync:init`
- **预期**执行上下文准备：输出 git 状态到 `.docsync/context/git-status.txt`、生成 Repomix 上下文、扫描 Markdown 文档清单

##### 场景：sync 中的上下文准备

- **当**用户运行 `/docsync:sync`
- **预期**刷新 git 状态摘要、扫描项目文件、生成或刷新 Repomix 上下文

### 新增需求

#### 需求项：Repomix 上下文生成

系统必须通过 Repomix 生成项目代码上下文。

##### 场景：Repomix 成功

- **当**Repomix 可执行（npx 或全局）
- **预期**生成 `.docsync/context/repomix-output.xml`

##### 场景：Repomix 失败

- **当**Repomix 命令执行失败
- **预期**停止并报告失败原因

#### 需求项：git 状态摘要

系统必须生成 git 状态摘要。

##### 场景：git 仓库

- **当**项目是 git 仓库
- **预期**输出 `git status` 到 `.docsync/context/git-status.txt`

##### 场景：非 git 仓库

- **当**项目不是 git 仓库
- **预期**生成空状态文件或标注"not-a-git-repo"

#### 需求项：文档清单扫描

系统必须扫描项目中的 Markdown 文档清单。

##### 场景：扫描文档

- **当**扫描项目目录
- **预期**生成 `.docsync/context/docs-inventory.json`，包含所有 .md 文件路径

## 2. 技术契约（SDD 扩展）

### 2.1 接口定义

#### docs-inventory.json 结构

```json
{
  "scannedAt": "2026-05-27T00:00:00.000Z",
  "files": ["README.md", "CLAUDE.md", "AGENTS.md", "docs/guide.md"]
}
```

---

## 3. 物理约束

| 指标 | 约束值 | 说明 |
|------|-------|------|
| Repomix 生成耗时 | < 15 秒 | 典型项目 |
| git 状态输出 | < 1 秒 | 任何项目 |
| 文档扫描耗时 | < 500ms | 递归扫描 .md |

## 4. 影响模块

### 4.1 内部依赖

- [ ] `src/core/context.mjs`：上下文生成

### 4.2 外部依赖

| 组件类型 | 组件名称 | 版本 | 用途 | 降级策略 |

## 5. 安全与合规

### 5.1 权限要求

- 只读项目文件
- 写入 .docsync/context/

### 5.2 数据安全

- 不读取 .env、密钥文件

### 5.3 审计要求

- 无

### 6.1 接口兼容性
