## 1. 需求规格（官方格式）

### 修改需求

#### 需求项：npx 默认入口行为

系统必须将无参数执行作为 npx 引导入口，替代旧的子命令分发行为。

##### 场景：无参数执行

- **当**用户执行 `npx @hunterzheng/docsync`（无子命令）
- **预期**进入交互式引导流程，而非展示帮助信息

##### 场景：help 子命令

- **当**用户执行 `npx @hunterzheng/docsync help`
- **预期**展示所有可用命令，包括新引导入口和 legacy 命令

#### 需求项：旧命令 legacy 兼容

系统必须保留旧命令作为兼容层，在帮助信息中提示迁移。

##### 场景：执行旧命令

- **当**用户执行 `docsync init` 或 `docsync prep`
- **预期**命令仍可执行，但帮助信息中提示"此命令已迁移到 npx 引导和 /docsync:* 指令"

##### 场景：旧命令 help 输出

- **当**用户执行 `docsync help`
- **预期**展示新命令路径（npx 引导 + /docsync:*），旧命令标记为 legacy

### 新增需求

#### 需求项：命令分发重构

系统必须重构 `src/cli.mjs` 以支持新的入口行为。

##### 场景：入口分发

- **当**CLI 启动
- **预期**判断是否有子命令参数，无参数则进入引导流程，有参数则分发到对应命令

## 2. 技术契约（SDD 扩展）

### 2.1 接口定义

#### 命令分发逻辑

```
bin/docsync.mjs → src/cli.mjs
  ├─ 无参数 → npx bootstrap (src/commands/init.mjs)
  ├─ help → 帮助（含 legacy 提示）
  ├─ init → npx bootstrap（新）或 legacy（兼容）
  ├─ prep → 提示迁移到 /docsync:sync
  ├─ ai → 提示迁移到 /docsync:sync
  └─ ... → 现有命令分发
```
