## 1. 需求规格（官方格式）

### 修改需求

#### 需求项：init 命令重构为 npx 引导

系统必须将旧的 `docsync init` 命令重构为 npx 引导流程，包含 6 个阶段的完整引导。

##### 场景：npx 引导完整流程
- **当**用户执行 `npx @hunterzheng/docsync`
- **预期**按顺序执行：阶段1定位目录 → 阶段2环境检查 → 阶段3AI工具选择 → 阶段4安装工作区 → 阶段5安装适配器 → 阶段6初始化三份文档

##### 场景：旧 docsync init 兼容
- **当**用户执行 `docsync init`
- **预期**行为与 npx 引导一致，但提示迁移到 npx

### 新增需求

#### 需求项：阶段化引导

系统必须实现固定的 6 阶段引导流程，任一步骤失败则 fail-fast。

##### 场景：阶段 1 定位目录
- **当**引导流程开始
- **预期**确定目标目录（默认 cwd），检查可写性，检查危险目录，检查 git 仓库

##### 场景：阶段 2 环境检查
- **当**目录定位通过
- **预期**检查 Node.js >= 18、npm/npx 可执行、git 可执行、目录可写；推荐项检查 Repomix、markdownlint-cli2、AI 客户端

##### 场景：阶段 3 AI 工具选择
- **当**环境检查通过
- **预期**交互式询问用户选择 Claude Code / Codex / All

##### 场景：阶段 4 工作区安装
- **当**AI 工具选择完成
- **预期**创建 `.docsync/` 完整目录结构，写入默认配置和规则

##### 场景：阶段 5 适配器安装
- **当**工作区创建完成
- **预期**根据选择安装 Claude Code Skill 或 Codex AGENTS.md 或两者

##### 场景：阶段 6 文档初始化
- **当**适配器安装完成
- **预期**检查三份核心文档，不存在则创建，存在则补缺 DocSync 必需结构

## 3. 物理约束

| 指标 | 约束值 | 说明 |
|------|-------|------|
| 引导总耗时 | < 5 秒 | 不含 npx 下载时间 |
