# spec.md - 能力规格定义

> **定位**：npx 无参数引导入口能力
>
> **【质量红线】严禁描述模糊；约束必须量化；缺失必要参数时 opsx-check 必须报错拦截

>> **【格式要求】** 需求项使用 `####`（4个#），场景必须使用 `#####`（5个#）

## 1. 需求规格（官方格式）

### 新增需求

#### 需求项：npx 无参数引导入口

系统必须支持 `npx @hunterzheng/docsync` 无参数启动项目引导流程，不要求用户追加 `init` 或其他子命令参数。

##### 场景：默认无参数启动
- **当**用户在项目根目录执行 `npx @hunterzheng/docsync`
- **预期**CLI 进入交互式引导流程，开始阶段 1（定位项目目录）

##### 场景：显式最新版写法
- **当**用户执行 `npx @hunterzheng/docsync@latest`
- **预期**行为与无参数启动完全一致，显式指定拉取最新版本

##### 场景：带参数但不合法
- **当**用户执行 `npx @hunterzheng/docsync --unknown-flag`
- **预期**展示帮助信息并提示正确的无参数用法

#### 需求项：项目目录定位与安全检查

系统必须在引导阶段 1 中定位目标目录并执行安全检查。

##### 场景：当前工作目录可用
- **当**当前工作目录存在且可写
- **预期**继续执行阶段 2

##### 场景：危险目录拦截
- **当**当前工作目录位于用户 home 根目录或磁盘根目录
- **预期**停止并提示用户选择更安全的项目目录

##### 场景：非 git 仓库提示
- **当**当前目录不是 git 仓库
- **预期**提示用户确认是否继续，默认不静默继续

#### 需求项：环境检查

系统必须在引导阶段 2 中执行环境检查，必需项失败立即停止。

##### 场景：全部必需项通过
- **当**Node.js >= 18、npm/npx 可执行、git 可执行、目录可写
- **预期**继续执行阶段 3

##### 场景：Node.js 版本不足
- **当**Node.js 版本 < 18
- **预期**停止并提示 "Node.js >= 18 required, current: vX.Y.Z"

##### 场景：推荐项缺失
- **当**Repomix 或 markdownlint-cli2 未全局安装
- **预期**继续执行，记录为推荐项缺失，引导完成后在总结中明确提示

##### 场景：AI 客户端缺失
- **当**用户选择 Claude Code 但 `claude` 未安装
- **预期**提示缺失但允许继续安装项目 Skill

#### 需求项：AI 工具选择

系统必须在引导阶段 3 中交互式询问用户选择 AI 工具。

##### 场景：选择 Claude Code
- **当**用户选择 "Claude Code"
- **预期**记录 aiTool = "claude" 到 install.json，后续安装 Claude 适配器

##### 场景：选择 Codex
- **当**用户选择 "Codex"
- **预期**记录 aiTool = "codex" 到 install.json，后续安装 Codex 适配器

##### 场景：选择 All
- **当**用户选择 "All"
- **预期**记录 aiTool = "all" 到 install.json，后续安装两个适配器

#### 需求项：fail-fast 停止策略

系统必须在引导流程任一步骤失败时立即停止，不继续执行后续步骤。

##### 场景：阶段 2 环境检查失败
- **当**Node.js 版本检查失败
- **预期**停止执行，不进入阶段 3，明确告知用户失败阶段为"环境检查"

##### 场景：阶段 4 工作区创建失败
- **当**无法创建 .docsync/ 目录（权限不足）
- **预期**停止执行，不进入阶段 5，明确告知用户失败阶段为"工作区创建"

## 2. 技术契约（SDD 扩展）

### 2.1 接口定义

#### 接口基本信息
- **路径**：CLI 入口 `bin/docsync.mjs`
- **方法**：无参数执行
- **内容类型**：终端交互

#### 请求参数

| 参数名 | 类型 | 必填 | 说明 | 示例值 | 约束条件 |
|-------|------|------|------|--------|----------|
| 无 | - | - | npx 无参数启动 | `npx @hunterzheng/docsync` | 不接受位置参数 |

#### 错误码定义

| 错误码 | 含义 | 触发条件 |
|-------|------|----------|
| ERR_NODE_VERSION | Node.js 版本不满足 | Node.js < 18 |
| ERR_DIR_UNWRITABLE | 目录不可写 | 无写权限 |
| ERR_DANGEROUS_DIR | 危险目录 | home 根目录或磁盘根目录 |

## 3. 物理约束

### 3.1 性能约束
| 指标 | 约束值 | 说明 |
|------|-------|------|
| 引导启动时间 | < 2 秒 | 从 npx 下载到开始交互 |
| 环境检查耗时 | < 1 秒 | 全部必需项检查 |

### 3.2 资源约束
| 资源 | 限制 | 说明 |
|------|------|------|
| 内存 | < 50 MB | 引导进程峰值内存 |

### 3.3 超时配置
- 连接超时：不适用（本地 CLI）
- 读取超时：不适用
- 总超时：不适用

## 4. 影响模块

### 4.1 内部依赖
- [ ] `bin/docsync.mjs`：默认无参数入口行为
- [ ] `src/cli.mjs`：路由分发
- [ ] `src/commands/init.mjs`：npx 引导主入口

### 4.2 外部依赖

| 组件类型 | 组件名称 | 版本 | 用途 | 降级策略 |
|---------|---------|------|------|--------|
| 运行时 | Node.js | >= 18 | 执行环境 | 停止并提示 |
| 包管理器 | npm/npx | >= 9 | npx 执行 | 停止并提示 |
| 版本控制 | git | >= 2.x | 仓库检测 | 提示用户确认 |

### 4.3 数据存储
- 无数据库
- 文件系统：`.docsync/state/install.json`

---

## 5. 安全与合规

### 5.1 权限要求
- 仅需要项目目录写权限
- 不要求 sudo 或管理员权限

### 5.2 数据安全
- 不读取或输出 .env、token、密钥文件
- 不上传任何项目内容到远程

### 5.3 审计要求
- 引导结果写入 `.docsync/state/install.json`
- 记录安装时间、包版本、选择的 AI 工具、文件清单

---

## 6. 兼容性

### 6.1 接口兼容性
- 是否向后兼容：是
- 版本控制策略：旧命令保留为 legacy alias

### 6.2 数据兼容性
- 数据迁移方案：无
- 回滚策略：删除 `.docsync/` 目录即可
